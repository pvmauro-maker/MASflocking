# Bitcoin Market ABM — NetLogo

An agent-based model (ABM) of a simplified Bitcoin market, developed in NetLogo.

The model couples a **flocking-style agent system** (three heterogeneous species moving in an abstract 2D decision space) with a **Bitcoin price** that works in two phases: first it replicates an exogenous price series (synthetic or historical), then it switches to an **endogenous price** driven by the agents' own order imbalance.

The project is in an experimental/development stage.

## Project idea

The world is an abstract decision space, not physical space:

- the **X coordinate** encodes market activity (how likely an agent is to trade);
- the **Y coordinate** encodes the buy/sell bias (y >= 0 buys, y < 0 sells).

Three agent species:

| Breed | Role | Y drift |
|---|---|---|
| `agents-a` (yellow) | Trend followers | `+h * return` |
| `agents-b` (red) | Contrarians | `-h * return` |
| `agents-c` (cyan) | Neutral agents | `0` |

Species C has no directional response to returns and no fundamental value signal; it acts as a neutral/noise component.

Agents interact through intra-species flocking, inter-species repulsion, market-driven movement and probabilistic trading, with individual Bitcoin and cash holdings.

## Two-phase price mechanism

### Phase 1 — exogenous price

`model-price`, `model-return` and `model-volatility` are copies of the real/synthetic series. Agents react to the price but do not affect it.

### Phase 2 — endogenous price

The price is generated by the agents' orders:

```
ln p_{t+1} = ln p_t + mu * D_t
D_t = (bought - sold) / (N * trade-size)      in [-1, 1]
```

where `mu` is `price-sensitivity` and `D_t` is the excess demand computed from the **executed** orders accumulated since the last price update (`model-net-flow`). The price is floored at 1.

### Switch Phase 1 → Phase 2

The switch happens when the mean Pearson correlation between model volume and real volume (rolling window of `window-size`) stays at or above `pearson-threshold` for more than `min-ticks-above` consecutive trade ticks. Alternatively, it can be forced at a given day with `force-phase2-day` (> 0).

> **Note:** synthetic scenarios have zero real volume, so the correlation criterion never triggers. With synthetic scenarios use `force-phase2-day`.

## Hype and endogenous hysteresis

Market stress is represented by a hype variable with memory and a drawdown term:

```
H_t = max( |r_t| + sigma_t + w * DD_t ,  rho * H_{t-1} )
DD_t = max(0, (ATH_model - p_t) / ATH_model)
```

- `w` = `drawdown-weight`, `rho` = `hype-persistence`;
- `ATH_model` is the all-time high of the model price.

Hype lowers the agents' stubbornness, i.e. their tendency to keep their own direction instead of aligning with their flockmates:

```
stubbornness = clip( 0.95 - hype-sensitivity * H_t , 0.05 , 0.95 )
```

Because `H` remembers past shocks and drawdowns, the system shows a **path-dependent (hysteretic) response** that emerges from the agents' behaviour. It is not a multiplier applied afterwards to the volumes.

## Agent movement

At every tick, each agent:

1. **Flocks**: its velocity direction is blended with the mean unit-velocity direction of its flockmates (a fixed network of `number-of-followers` agents of the same species), weighted by the stubbornness. The speed is preserved.
2. **Repels** agents of other species within `repulsion-radius`.
3. **Swims**:

```
v_x <- v_x * (1 - velocity-damping) + k * volatility - restoring-strength * x / max-pxcor
v_y <- v_y * (1 - velocity-damping) + (±h * return) - restoring-strength * y / max-pycor
```

   followed by reflecting boundaries and a random rotation of the velocity within ±`temperature`.

Volatility and return are those of the model (`model-volatility`, `model-return`), which in Phase 1 coincide with the real series.

## Trading mechanism

On every trade tick (every `trade-interval` ticks):

- the agent trades with probability proportional to its normalized X position;
- it **buys** if `y >= 0` and **sells** if `y < 0`;
- the quantity is at most `trade-size`, limited by available cash (buy) or held Bitcoin (sell);
- the model records the traded volume (BTC and USD) and the net order flow.

## Parameters

Everything is set from the Interface tab (sliders/chooser):

| Group | Parameters |
|---|---|
| Population | `population-a`, `population-b`, `population-c`, `number-of-followers` |
| Current | `k` (x = k·volatility), `h` (y = ±h·return) |
| Motion | `temperature`, `velocity-damping`, `restoring-strength`, `repulsion-radius`, `repulsion-strength`, `spawn-radius` |
| Trading | `trade-size`, `trade-interval`, `initial-wealth-btc` |
| Price | `price-sensitivity` (mu), `scenario`, `num-days` |
| Hype | `hype-sensitivity`, `hype-persistence` (rho), `drawdown-weight` (w) |
| Phase switch | `pearson-threshold`, `window-size`, `min-ticks-above`, `force-phase2-day` |

## Scenarios

- `bull-market`, `bear-market`, `sideways`: geometric random walk with drift and noise;
- `crash`: stable period, then a sudden large decline, then recovery;
- `bubble`: growth → euphoria → collapse → post-bubble stabilization;
- `csv`: historical data from `dati_btc.csv` (columns: index, price, optional volume).

Synthetic scenarios have zero volume. The `api-live` scenario was removed.

## Outputs

**Plots** (names as in the Interface):

- `Prezzo BTC (USD)`: real price and model price;
- `Volume BTC (USD)`: model volume and real volume;
- `Correlazione Volumi (Pearson r)`: instantaneous and mean correlation, with the switch threshold;
- `Correlazione Prezzi (Pearson r)`: correlation between **returns** (model vs real), as a diagnostic.

**Reporters for monitors:**

- order parameters: global, A, B, C;
- Bitcoin and cash held (total and per species);
- mean Y position of agents A and B.

## Running the model

1. Open the `.nlogo` file in NetLogo.
2. Configure the parameters in the Interface tab.
3. Choose a `scenario`.
4. Press **Setup**, then **Go**.

The run stops automatically when the data series ends.

## Known issues and limitations

- `bilancia-portafogli` currently has no effect: it runs before the agents are created and with `model-price = 0`, then `inizializza-agente` overwrites the holdings with random values. As a result `initial-wealth-btc` is ignored.
- Some constants are still hard-coded: base/min stubbornness (0.95 / 0.05), the volatility floor in Phase 2 (0.005), and the phase times of the `crash` and `bubble` scenarios (days 100/110/115).
- The correlation switch cannot trigger with synthetic scenarios (zero volume).
- Simplifications: no order book, no bid/ask spread, no transaction costs, no liquidity constraints, no external participants, simplified link between position and trading.
  

## Main research question

Can heterogeneous agent behaviour generate realistic patterns in aggregate trading volume, and can the order imbalance of the same agents sustain a plausible endogenous price?
